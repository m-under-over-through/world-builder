# Services

Draft 0.2, 23 October 2026. Companion to the architecture and risk plan. Revised the same day after the decision to use a subdomain of under-over-through.co and the existing UOT GitHub account (ADR 0010).

**The rule.** Free tiers are fine where there is no state and a redeploy takes under an hour. Pay for anything that holds data or that must never pause. Every service below has one owner (you), two-factor authentication on, printed recovery codes with the key envelopes, and an entry in the runbook saying what breaks if it goes away.

## 1. What you already have, and how it is used

**under-over-through.co.** The app lives on a subdomain of it, `worldbuilder.under-over-through.co`, with the workshop in the path. Checked on 23 October: DNS is hosted at Netlify (on the NS1 network), mail is Google Workspace, the main site is on Netlify, sets no cookies and loads no third-party scripts. So the subdomain inherits nothing that would contradict the trust page, and adding the app is one CNAME record. The name must not contain an underscore: DNS allows it, certificate authorities do not, and browsers would not reach it over HTTPS. The domain's registrar, expiry date and auto-renew setting go into the runbook, because the app now depends on a registration the business already depends on.

**Netlify, free.** Stays exactly where it is: the DNS host for the domain and the host of the main site. It does not host the app. The free plan is single-member and pauses a site that exceeds its allowance, which is the "URL does not work" failure, so the app goes on Cloudflare Pages via that one CNAME.

**Google Workspace.** The `privacy@under-over-through.co` contact address is an alias or group there. No mail-forwarding service needed.

**GitHub, the UOT account.** Two repositories under it: the app repository (client, API, deck engine, deck content, docs) is public, which is what makes the "check the source" claim on the trust page true; the ops repository (backup workflow, runbook pages naming vendor specifics, drill scripts) is private, so a misconfigured job can never print a connection string into a public log. The nightly backup uses about 60 of the 2,000 free CI minutes a month. On a free personal account branch protection works only on the public repository; acceptable, since only you push to the private one. An organization is not needed while there is one owner; if a second one appears, repositories transfer into an organization in minutes and the old URLs redirect.

## 3. Deliberately not used

- **A new domain.** A subdomain of the organizer's own domain is more recognisable to participants and one less registration to keep alive.
- **Moving the domain's DNS to Cloudflare.** It would put everything in one dashboard, but means recreating the mail and site records by hand. Not worth risking the business domain for this project.
- **Analytics, error reporting, session replay** (Google Analytics, Plausible, Sentry, Hotjar). Each one makes the app talk to a third domain and breaks the one-host claim. Aggregate numbers come from your own database; client errors are shown in the diagnostics panel and, if you want them centrally, posted to your own API with no identifying fields.
- **Google Fonts, icon CDNs, script CDNs.** Self-host everything.
- **CAPTCHA.** Friction and a third party. Wave windows, invite links and rate limits do the job.
- **An email-sending service.** The app never emails anyone. Alerts come from the monitor, not from your code.
- **A virtual server you administer.** Patching, disks and reboots are a second job. Managed services only.
- **Netlify for the app.** Workable, but the free plan can pause the site and the API would need a second vendor anyway.

## 4. Account hygiene, once at setup

- Every account under the UOT identity or a project email, never a personal login.
- Two-factor on everywhere, with an authenticator app, not SMS.
- Recovery codes printed and stored with the key envelopes.
- Billing on one card with alerts on, and the expiry date written in the runbook next to the domain renewal date.
- The domain's registrar, expiry date and auto-renew setting recorded in the runbook. The app lives or dies with that renewal.
- Vendor logging set to the minimum each allows, and the setting noted on the trust page.
- A page in the runbook per service: what it does, where the login is, what breaks without it, how to move off it.
