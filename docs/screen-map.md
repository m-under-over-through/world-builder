# Screen map

Every screen and state of the client, with the error codes it can show. The UI builder builds this; it does not invent screens. Copy comes from `workshops/<slug>/copy.md`.

All routes live under `/<slug>/`. Storage on the device is namespaced by slug.

The top bar is the workshop's name and nothing else. The foot of every screen is one small link, "About this app", to the one page that explains the app, shows the code and the facts, and deletes everything (ADR 0013). That page and the two texts have their own foot.

## Entry

| Route                    | Screen         | Notes                                                                                                                                                                                                                                                                                                                        |
| ------------------------ | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/<slug>/join/<wave>`    | Wave landing   | Posts `waveOpened` once per device, the first time this device arrives through this wave. The address stays, so the page can be shared or carried to another device. If a code is already stored: go to Next card. Else: Welcome with the wave remembered. Errors: `JOIN_WAVE_UNKNOWN`, `JOIN_WAVE_FULL`, `WORKSHOP_CLOSED`. |
| `/<slug>/join/i/<token>` | Invite landing | Same, with the invite remembered and the address replaced by `/<slug>/`, so the single-use token does not linger. Errors: `JOIN_INVITE_INVALID`, `JOIN_INVITE_USED`.                                                                                                                                                         |
| `/<slug>/`               | Welcome        | One button, "New here" (needs a remembered wave or invite; otherwise the screen explains it needs a link), and under it one quiet line with the "I have a code" text link. After a stored code was refused on open (`AUTH_CODE_UNKNOWN`), one calm line says the code was forgotten here; no box, and only then.             |
| `/<slug>/continue`       | Enter code     | 16-digit field, groups of four, numeric keypad. `GET /me` with the code. Error: `AUTH_CODE_UNKNOWN` ("that code is not ours; check the digits"). On success: Next card.                                                                                                                                                      |

## Core loop

| Screen        | States                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Card          | `fresh` (question, answer field, "Set aside"), `answering` (keyboard up, nudge "please do not name real people", counter near 4,000; the limit is counted and enforced by code points so an emoji is never cut in half), `saving` (sealing, writing the outbox), `saved` ("Saved on this device"), `synced` ("Synced"). Swipe or "Set aside" writes `dismissed`; a second dismissal of the same card writes `deferred`.                                            |
| Session end   | One heading, "Thank you", and nothing said twice. Session 1: the code in one sentence ("If you ever want to continue on another phone, this is you: [code]"), in groups of four, shown plainly, with Copy; then the install offer where it is due; then the come-back line. Every session: "The next cards wait for you another day" once, with the "Remind me" link; and, only while answers wait on the phone, a quiet line with the count.                      |
| Install offer | Session 1 only, under the code, shown once and never again; nothing has to be tapped. The steps for this platform; on Android with the browser's own offer, an "Install" button. On Android the installed app shares the browser's storage, so it continues. On an iPhone it has its own and asks for the code once, and the steps say so; it is offered even so, because a home-screen app is exempt from Safari's seven-day deletion of site storage (ADR 0013). |
| Remind me     | A link to `/<slug>/reminder.ics`, a calendar file the phone's own calendar adds: twice a week (Wednesday and Sunday, 18:00 local) from the day after the workshop opens until its close day, with an alarm, carrying the workshop's home link and nothing else. Written at build, one per workshop (`apps/web/pwa.ts`, `apps/web/src/lib/reminder.ts`).                                                                                                            |

## Offline and failure behaviour

- No network: everything works; events wait in the outbox; the card shows "Saved on this device". The join itself can be queued.
- After a server restore: the device keeps accepted events for fourteen days; on open it compares them with `GET /me` and re-sends any the server lacks, silently.
- `AUTH_CODE_UNKNOWN` on a stored code (the participant was deleted, or the workshop was reset): clear the stored code and show Welcome with one calm line that says so.
- `WORKSHOP_CLOSED`: a closing screen, with the page about the app at its foot as on every screen; no new events are created.
- `CLIENT_STORAGE_UNAVAILABLE`: the app still runs for one session, warns that the code cannot be kept, and shows it at the end.
