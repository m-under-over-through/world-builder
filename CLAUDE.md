# Instructions for agents working in this repository

This is World Builder: a card-based reflection app for participatory future-building workshops.
Read these before touching anything, in this order:

1. `README.md`, the map of the repository.
2. `docs/glossary.md`. The glossary is law: use these words, no synonyms, no new words without proposing them.
3. `docs/architecture-and-risk-plan.md`, sections 5, 6, 9, 10 and 12.
4. `docs/design-and-development-plan.md`, sections 4, 6 and 7.
5. The decision records in `docs/adr/`.

## Non-negotiables

- **No personal data, ever.** No column, log line, header, URL or error message may carry a name, an email, an IP address, a user agent or a precise timestamp. Days only.
- **The client talks to one origin.** No third-party scripts, fonts, images, analytics or error reporting. The Content Security Policy is `self` only and stays that way.
- **The anonymous code never appears in a URL or a log.** It travels in the `Authorization` header and is stored as a keyed hash.
- **Answers are sealed on the device.** The API never imports `@wb/crypto` and never sees plain text. No readable answer is kept on the device after sync.
- **Everything is scoped to a workshop.** Every table with participant data has a workshop id; every query filters on it; a test proves cross-workshop reads return nothing.
- **Events are append-only** with client-generated ids. No updates in place, no deletes except the participant's own "delete me".
- **Every failure path has an error code** in `packages/contracts/src/api.ts` and an entry in `docs/runbook.md`.
- **No new dependency or service** without a line in `docs/services.md` or a decision record saying why.
- **Secrets never enter the repository.** Development keys live in `.secrets/` (gitignored). Production keys are generated by the operator and go to the vault.

## Ownership

- `packages/contracts` is owned by the integrator. Builders propose changes in their report; they do not edit it.
- One builder per set of files at a time. A brief names the files a builder owns; stay inside them.
- Anything not covered by the architecture plan gets a decision record in `docs/adr/` before the code lands.

## How the code is written

- TypeScript, strict, ESM. Relative imports carry the `.ts` extension (Node runs the tools without a build step).
- Schemas with Zod in `@wb/contracts`; validate at every boundary; derive types from schemas, never the other way round.
- Tests with Vitest in `packages/*/test`, named as behaviours: "a request with an unknown code gets a 401 and no data".
- Formatting with Prettier. `npm run check` runs typecheck, tests and formatting; it must pass before any commit.
- Comments explain why, and point to the learning note or decision record that explains the idea.
- Plain words in docs and comments. Short sentences. No em-dashes.

## Every change ships with

1. Tests for the behaviour it adds or changes.
2. A commit message or pull request description with: what changed and why; **how to verify by hand**; error codes added; the decision record it follows.
3. An entry in `docs/build-log.md` (date, what, why, how to verify, decisions made on the way, open questions). When the change introduces an idea the operator has not met in this project yet, add or extend a note in `docs/learn/` and link it from the log entry. The operator reads every entry; write for someone who understands systems at a high level and wants to see the actual procedure.
4. A runbook entry for every new error code.

## Notes for builders, from the first review

- **API builder.** The API is a Netlify Function: a web-standard fetch handler that calls `app.fetch`; Neon through the serverless HTTP driver; secrets from Netlify environment variables, with separate values for the staging branch deploy (ADR 0011). Cap the request body in bytes before parsing JSON; a schema can only bound what is already parsed. Persist only the parsed value, never the raw body. Join shares the rate limit of the authenticated routes. Compare invite tokens as strings, never decoded. Health publishes nothing per workshop beyond its status.
- **UI builder.** Truncate answers by code points, not by string length; half an emoji is refused by `sealAnswer` with `CRYPTO_BAD_TEXT`. Call `sealAnswer` before writing to the outbox so nothing unsendable is ever stored. Keep events the server has accepted for `EVENT_RETENTION_DAYS` and, on open, re-send any whose id is missing from `GET /me`. Split sync batches by `SYNC_MAX_EVENTS` and by `MAX_REQUEST_BYTES`.
- **Everyone.** Create files that must not be overwritten with `flag: 'wx'`. Anchor paths on `import.meta.url`, not the current directory. Reject unknown command-line flags.
